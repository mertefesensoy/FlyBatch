## 1. Problem / motivation

Every engine target of the build compiled Berkeley SoftFloat Release 2c,
whose terms ask the user to accept all losses and to indemnify its author
(`THIRD_PARTY_NOTICES.md`, section 3). D-679 gave a contributor who refuses
those terms `make test-no2c`, but that ran only the 15 checks that never had
a 2c half, so it did not test the engine. An engine contributor who refused
2c's terms had nothing to run.

The risk in fixing that is the opposite one. Every comparator already
accepts two programs as readily as three, so a build that quietly dropped
SOFT2C would look like a green run of all three backends, with only a
smaller line count to show it. Anything that leaves 2c out therefore has to
say so, in a way that can never be read as the full suite: not by a
person, and not by a script reading 11.8's closing line.

## 3. Implementation approach

**The switch.** `NO2C=1`, on the command line or in the environment.
Unset, empty or `0` gives the full build; any other value stops make at
parse time with `NO2C is '<value>'; expected 1, 0 or unset (P-52)`, so a
mistyped switch can never compile 2c quietly. GNU make exports a
command-line variable to recipes and passes it to sub-makes through
`MAKEFLAGS`, so `tools/testrun.py`'s sub-makes and the marker's own
command line both see it (measured on GNU Make 3.82.90, P-52 S8).

**Each target with a 2c half.** The 2c build and run lines sit in the
`else` branch of an `ifeq` inside the recipe; the `NO2C=1` branch is one
line, `$(PYTHON) tools/onfres.py no2c <target>/SOFT2C`, at the point where
the 2c half would have run. Comparator lines name the 2c program through
`$(call WITH2C,...)`, which is empty under the switch, so the SOFT3E and
NATIVE comparisons are one shared line, not two copies. The 2c
prerequisites `$(SF2CSRC) generated/onf2cnm.h` come through `SF2CDEP`,
also empty under the switch, so make neither derives the 2c sources nor
builds their name map. `c2c` and `c04mvs` are 2c and nothing else, so
their whole rule is conditional and their `NO2C=1` form is the marker
alone. `shim` has no 2c of its own and is unchanged.

**The marker (D-691).** `onfres.no2cline(check, reason, env)` returns
`("ONFRES NO2C <check>: <reason> [D-691]", fatal)` and writes nothing;
`fatal` is true only in strict mode, and then unless `NO2C=1` is in `env`
and `check` is one of the nine `NO2C_HALVES`. `onfres.no2c()` prints it and
exits 1 when it is fatal. It is never an exemption: an exemption is a skip
no clone can clear (D-548), and this one is cleared by accepting the terms.

**The runner (D-691).** `testrun.verdict(target, marks)` returns SKIP if
the sub-make printed any SKIP marker, as D-549 has it; NO2C if a NO2C
marker's check name has `target` as its prefix before `/`; otherwise PASS.
The asymmetry exists because TESTS names `shim` before `fp`: `fp`'s recipe
runs inside `shim`'s sub-make and prints `fp/SOFT2C` there, while `shim`'s
own comparison ran whole. For the same reason the NO2C count is of distinct
check names. A run that saw any NO2C marker closes in its own form; one
that saw none closes as before, byte for byte.

**The two tests that ask make itself.** `t_dryrun` runs `make -n -B` for
each TESTS target but `onfres` with and without `NO2C=1`, with
`MAKEFLAGS`, `MAKELEVEL` and `NO2C` removed from the environment and
`TFPREREQ=` passed, and joins continuations and collapses whitespace
before comparing. `onfres` is left out because GNU make runs a recipe line
naming `$(MAKE)` even under `-n`, and `onfres`'s recipe passes `"$(MAKE)"`
to this very test. A static check fails if any other TESTS recipe names
`$(MAKE)`, and `ONFLY_DRYRUN` reports a nested run as a counted skip. The
sweep then dry-runs every other Makefile target under `NO2C=1`, pinning the
seven that run make (`all onfres quick test test-no2c test-nonet
testfloat`).

## 4. Mathematical / numerical details

None in the engine: no floating-point operation, order or constant
changes, and the engine's C source is not touched. The counting rules are
these, for a run over targets T:

- PASS = |{t in T : t's sub-make exits 0, prints no SKIP marker, and
  prints no NO2C marker whose check is t/...}|
- NO2C = |{distinct check names c : some sub-make printed `ONFRES NO2C c`}|
- SKIP, PENDING and EXEMPT count marker lines, as D-548 and D-549 have it.

So for `test` under `NO2C=1`, PASS = 29 - 9 = 20 and NO2C = 9; for
`test-nonet`, 23 - 7 = 16 and 7; for `quick`, 2 - 2 = 0 and 2. `shim` is a
PASS in both, though `fp/SOFT2C` prints twice. The measured TestFloat case
counts follow the same arithmetic: `run_tt02` checked 520,752 cases on two
backends and 781,128 on three, exactly two thirds.

## 5. Design decisions

| Decision | Chosen | Alternatives | Who |
|---|---|---|---|
| The plan | P-52 as drafted (D-690) | Change it; discuss it | The owner |
| How a left-out 2c half is counted | Its own NO2C kind, prefix-matched demotion, its own closing line, a two-condition strict rule (D-691) | An ordinary SKIP, tagged, same strict rule; an ordinary SKIP that strict mode fails | The owner, the engineer's recommendation |
| The name clash with D-679's list | List renamed `FREE2C`; `test-no2c` becomes `NO2C=1 test-nonet` (D-692) | Keep `test-no2c` as 15 targets; give the switch another name | The owner, the engineer's recommendation |
| CI | A seventh job, `no2c-linux` (D-693) | That plus `NO2C=1 quick` in `golden`; no new job | The owner, the engineer's recommendation |
| `runners` and `tf2`, found during the work | Covered: `runners` builds no 2c runner, `tf2` refuses (D-694) | Leave them, NO2C=1 for test targets only | The owner, the engineer's recommendation |
| Comparator lines | One shared line with `$(call WITH2C,...)` | Two copies, one per `ifeq` branch | The engineer: one copy cannot drift from the other |
| `c2c` and `c04mvs` under the switch | The marker alone, no prerequisites | Keep `$(BUILD)` and `$(GENERATED)` as prerequisites | The engineer: building the layout for a target that then does nothing is waste, and the dry-run walk states the rule exactly |
| The dry-run walk and `onfres` | Leave `onfres` out, pin the rest | Dry-run everything | Forced: `make -n onfres` runs this test, which would then run itself again |

**What this does not prove.** Nothing about SOFT2C, and so nothing about
MVS: a `NO2C=1` run builds no SOFT2C program, so Section 8.3 row 3b, the
x86-64 comparand of MVS rows 6 and 7, is not exercised, and neither are
`c2c` (2c against TestFloat) or `c04mvs` (the C-04 names of the MVS
objects). An engine change that passes under `NO2C=1` can still change a
SOFT2C fingerprint; CI's other jobs and the owner's full `make test` are
what catch that. A tester's NO2C result is not a Section 8.3 row and cannot
stand for row 3b (D-684). R5 shows that the engine targets need no 2c file
on this host; some checks outside them still read 2c's files as text (the
licence and notices lints, the MVS deck builders), which is D-679's
criterion, kept. `ONFPLAT=s390x` shares the mechanism, and its dry runs
pass, but no s390x build was run: the lab is down. CI is a smoke test
(D-586). This is a technical criterion only: it makes no claim about what
2c's terms require of anyone.
