## 2. The design

**2.1 The switch.** `NO2C=1`, given on the command line or in the
environment. An unset or empty `NO2C`, or `NO2C=0`, gives the full build,
with exactly the commands it runs today. Any other value stops make with an
error before anything is built, because a mistyped `NO2C=yes` must never
compile 2c quietly. D-679's list variable is renamed so that the switch can
have its name (Q3). The public target `test-no2c` keeps its own name.

**2.2 Each target with a 2c half.** The 2c lines of each of the nine recipes
go inside `ifeq ($(NO2C),1) ... else ... endif`. Under the switch, the 2c
build and run lines are replaced by one marker line, printed at the point
where the 2c half would have run, and the comparator lines drop the 2c
program. The 2c prerequisites (`$(SF2CSRC)`, `generated/onf2cnm.h`,
`generated/onf2cv.h`, and `c2c`'s `$(TFPREREQ)`) come from one variable,
which is empty under the switch.

| Target | Under `NO2C=1` | Marker |
|---|---|---|
| `fp` | SOFT3E and NATIVE against the oracle; `cmpback.py` on the two | `fp/SOFT2C` |
| `kernel` | The same, through `run_ker.py` | `kernel/SOFT2C` |
| `syn` | `gensyn.py --check`, then two backends and `cmpback.py` | `syn/SOFT2C` |
| `golden` | `tstgld` on two backends; `cmpgld.py`, and `cmpchk.py` at K in {1, 7, 250, 100000}, on the two | `golden/SOFT2C` |
| `tt02` | `run_tt02.py`, SOFT3E and NATIVE against TestFloat | `tt02/SOFT2C` |
| `eng` | `run_plim.py`, the four SOFT3E and four NATIVE builds, `run_eng.py` on each backend | `eng/SOFT2C` |
| `req` | `run_req.py` and `test_strm.py` on SOFT3E and NATIVE; `test_txcmp.py` unchanged | `req/SOFT2C` |
| `c2c` | Nothing built | `c2c/SOFT2C` |
| `c04mvs` | Nothing built | `c04mvs/SOFT2C` |
| `shim` | Unchanged. It carries the switch through `fp`, its prerequisite | none of its own |

`quick`, `test-nonet` and `test` need no change of their own, because
`testrun.py` passes `NO2C=1` to every sub-make through `MAKEFLAGS` (S8).
`SOFT2C` is the name the programs already print in their banners
(`backend=SOFT2C`).

**2.3 How the 2c half is counted (Q2).** The recommendation is a new
marker kind, printed by a new `tools/onfres.py` function. The marker comes
from a recipe line, so the function also gets a small command-line form,
`python tools/onfres.py no2c <check>`:

    ONFRES NO2C fp/SOFT2C: NO2C=1, SoftFloat 2c not built [<D-row>]

`tools/testrun.py` counts these markers in a fifth column. The two
demotion rules, stated mechanically:

- **SKIP, as today (D-549):** any SKIP marker in a target's sub-make
  demotes that target.
- **NO2C, new:** a NO2C marker demotes the sub-make's target only when the
  check name's prefix before `/` equals that target. The target's verdict
  in the per-target table is then `NO2C`, not `PASS`. SKIP wins over NO2C
  when a target prints both.

The NO2C count is the number of distinct NO2C check names seen in the run.
The asymmetry with SKIP, and the distinct count, both exist because of S11:
`fp/SOFT2C` also prints inside `shim`'s sub-make, and `shim`'s own
comparison, SOFT3E against the shimmed SOFT3E, still runs whole. If the run
saw any NO2C marker, the closing line becomes

    ONFLY test NO2C=1: <p> PASS, <s> SKIP, <q> PENDING, <e> EXEMPT, <n> NO2C (SoftFloat 2c not built: not the full suite; PASS counts targets; SKIP, PENDING, EXEMPT and NO2C count checks; D-548, D-549, <D-row>)

The counted line that 11.8 reads, a line matching `^ONFLY test: \d+ PASS`,
is never printed in a NO2C run, so it cannot be misread there. The headers
`ONFLY test: per target` and `ONFLY test: checks that did not run`, and the
failure line `ONFLY test: FAILED ...`, keep their prefix. A run with no NO2C
marker prints today's closing line, byte for byte.

The alternative is an ordinary SKIP named `<target>/SOFT2C`, with D-548's
three kinds unchanged and the closing line tagged in the same way. It is a
smaller change. But under 2.4's rule, a strict NO2C run would then pass with
SKIP above 0, which strict mode has never allowed, and declared omissions
would share a column with missing packages. **Never EXEMPT:** the exemption
table is for skips that no clone can clear (D-548). This skip is cleared by
accepting 2c's terms, and an exempt 2c half would let a strict NO2C run
close in today's line form.

**2.4 `ONFLY_NOSKIP=1` under the switch (Q2).** A NO2C marker does not fail
strict mode when two conditions hold: `NO2C=1` is in the process
environment, and the check name is one of the nine in a new `onfres.py`
table, each citing the D-row that approves this plan. If either condition
fails, the marker fails strict mode like an unexempt skip. Every other skip
fails strict mode exactly as it does today. So `ONFLY_NOSKIP=1 make NO2C=1
test-nonet` is a real strict run, and a missing package still fails it.

Expected closing lines under 2.3 and 2.4, all to be measured (W4):

| Command | Targets | With a 2c half | Expected |
|---|---|---|---|
| `make NO2C=1 test-nonet` | 23 | 7 (`c04mvs tt02 c2c fp kernel syn eng`) | `ONFLY test NO2C=1: 16 PASS, 0 SKIP, 0 PENDING, 2 EXEMPT, 7 NO2C` |
| `make NO2C=1 test` | 29 | 9 (those, `req` and `golden`) | `ONFLY test NO2C=1: 20 PASS, 0 SKIP, 0 PENDING, 5 EXEMPT, 9 NO2C` |
| `make NO2C=1 quick` | 2 | 2 | `ONFLY test NO2C=1: 0 PASS, 0 SKIP, 0 PENDING, 0 EXEMPT, 2 NO2C`, with both targets' SOFT3E and NATIVE halves green in the per-target table. 0 PASS is deliberate: neither target ran whole |
| `make test`, no switch | 29 | none built out | `ONFLY test: 29 PASS, 0 SKIP, 0 PENDING, 5 EXEMPT`, unchanged |

**2.5 `make test-no2c` (Q3).** The recommendation: `test-no2c` re-invokes
make as `NO2C=1 test-nonet`, so the one command a 2c refuser is told to run
now tests the engine. D-679's list is renamed `FREE2C` and kept as the
measured list of NONET targets that never had a 2c half. Its existing checks
still hold it to NONET's order and still fail if a NONET target free of 2c
is left out.

## 3. Work, in order

**W1, tests first, each shown failing before any Makefile or tool change.**

- (a) `tests/test_onfres.py`, onfres: the NO2C line's exact form. Not fatal
  under `ONFLY_NOSKIP=1` when `NO2C=1` is set and the name is declared;
  fatal when the name is undeclared or `NO2C=1` is missing. The command-line
  form prints the line. Every entry cites a real A.1 row. Fails now: there
  is no such function.
- (b) `tests/test_onfres.py`, testrun: `scan()` finds the NO2C kind. The
  fake Makefile of the end-to-end case gains a target that prints a NO2C
  marker, and a second target that has the first as a prerequisite. The
  runner is given the dependent target before the marker target, as TESTS
  names `shim` before `fp`. In the other order the dependent would get `-o`
  for the marker target, the marker would never print in its sub-make, and
  the check would prove nothing. Expected: the marker target's verdict is
  NO2C, the dependent's is PASS, the marker is counted once, the closing
  line has the `ONFLY test NO2C=1:` form, and no line matches
  `^ONFLY test: \d+ PASS`. A run with no marker keeps today's line (the
  existing check stays). `NO2C` and `MAKEFLAGS` are removed from that case's
  environment. Fails now: `scan()` ignores the kind, so the target counts as
  a PASS.
- (c) `tests/test_onfres.py`, the dry-run walk, which is the main proof.
  For each of the 29 TESTS targets it runs `make -n -B --no-print-directory
  TFPREREQ= <target>` twice, without and with `NO2C=1`, with `MAKEFLAGS`
  and `NO2C` removed from the environment and `ONFPLAT`, `PYTHON` and `CC`
  passed explicitly (S10).
  - Without the switch, the ten targets of S1 name 2c and the other 19 do
    not. So the test cannot pass because 2c vanished everywhere, and a
    target that gains a 2c half is noticed.
  - With the switch, no target names 2c. The patterns: `softfloat/c2c`,
    `SoftFloat-2c`, `derive2c`, `onf2cnm`, `onf2cv`, `ONF_FP_SOFT2C`,
    `onffp2.c`, `_2c.exe`, `obj2c`.
  - With the switch, every command is one of three things: the same
    command as in the full dry run; a full-run command with only its
    `_2c.exe` argument removed; or an `onfres.py no2c <t>/SOFT2C` marker for
    a target with a 2c half in the prerequisite closure. `make -n` prints a
    backslash-continued command as several lines, and dropping an argument
    moves the split, so the test joins continuations and collapses runs of
    whitespace before it compares. The 19 targets free of 2c have
    identical dry runs both ways. This is the property that the switch
    changes nothing but the 2c half: the SOFT3E and NATIVE programs are
    built by the same commands with and without it.
  - The onfres table's nine names are exactly the targets whose own recipe
    holds a 2c half, as the walk finds them.
  - `make NO2C=yes layout` stops with the error and builds nothing.
  Fails now: S4. Cost: about 9 s on this host, an estimate from S9's
  4.2 s per pass, added to `onfres`.
- (d) D-679's text walk learns to read both branches of a conditional
  inside a recipe, shown failing first on a fixture Makefile text inside the
  test (S9). Its list is renamed (Q3).

## 4. CI

The recommendation is a seventh job, `no2c-linux`, on `ubuntu-latest`,
built like `nonet-linux`:

1. `ONFLY_NOSKIP=1 make ONFPLAT=x86l PYTHON=python NO2C=1 test-nonet`, its
   output kept. The job fails unless the closing line is exactly
   `ONFLY test NO2C=1: 16 PASS, 0 SKIP, 0 PENDING, 2 EXEMPT, 7 NO2C (...)`
   and unless `find build` finds no 2c object. Pinning the numbers means a
   target that loses its marker, or gains one, fails the job.
2. Delete `third_party/SoftFloat-2c/` and `softfloat/c2c/` from the
   runner's checkout, remove `build/`, and run the eight NONET targets that
   reach 2c (`c04mvs tt02 c2c shim fp kernel syn eng`) through
   `tools/testrun.py`, strict, with `NO2C=1`. This is R5 on Linux: those
   targets need no 2c file.

The job's comment says what D-586 and VL-142 say for the others: a smoke
test on GitHub's gcc, never Section 8.3 evidence. W1's dry-run walk also
runs in every job that runs `tests/test_onfres.py` (`python-bare`, both
`nonet` jobs and `devcontainer`). The six existing jobs stay full, so they
keep compiling 2c on every push and every pull request, a NO2C
contributor's included. This plan does not change that.

## 7. What this will not prove

- **Nothing about SOFT2C, and so nothing about MVS.** A NO2C run builds no
  SOFT2C engine. Row 3b, the x86 comparand for MVS rows 6 and 7, is not
  exercised, and neither are 2c against TestFloat (`c2c`) or the C-04 names
  of the MVS objects (`c04mvs`). An engine change that passes under NO2C can
  still change a SOFT2C fingerprint. The full suite has to run before such a
  change is merged: in CI's full jobs on the pull request, and in the
  owner's `make test`.
- **A NO2C result is not a row.** A tester's NO2C result registered under
  D-684 says `NO2C=1` and cannot stand for row 3b.
- **R5 proves less than "never touches 2c".** It shows that the engine
  targets need no 2c file on the hosts where it ran. Some checks still read
  2c's files as text (S7), and that is D-679's criterion, kept here.
- **s390x is not run.** `ONFPLAT=s390x` shares the mechanism but gets no
  evidence, because the lab is down. CI is a smoke test only (D-586).
- **No legal claim.** The plan applies D-679's technical criterion (no 2c
  compile, link, run or derivation). It says nothing about what 2c's terms
  do or do not require of anyone.
